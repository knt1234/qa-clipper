# qa-clipper トラブルシューティング詳細

[SKILL.md](../SKILL.md) のトラブルシューティング表から遷移する詳細ページ。症状ごとの原因調査手順・手動コマンドをまとめる。

## 事後検証（qa_report.md）の4系統詳細

`verify_clips`（editor.py）が生成する `qa_report.md` は以下を検証する:

- **A. ファイル健全性**: 存在・サイズ、映像/音声ストリームの有無、実測長とa_end-q_startの一致（±1.5秒）、末尾フレームのデコード可否（尻切れ破損の検出）
- **B. 境界検査**: 冒頭・末尾6秒をfaster-whisper `tiny`モデルで文字起こしし、末尾に次の質問マーカーが混入していないか、冒頭が質問マーカーで始まっているかを確認
  - tinyモデルは高速な分、認識精度は粗い。マーカーの言い回しが誤認識されて「冒頭にマーカーが見当たらない」と誤検知することがある（既知の偽陽性。⚠️は自動失格ではなく目視確認のトリガーとして扱う）
- **C. カバレッジ検査**: クリップ間・前後の未使用区間のうち10秒を超えるものを、該当区間の文字起こし冒頭付きで報告（挨拶等で問題ないか、質問の取りこぼしかを判断する参考情報）。**総合判定の合否には含まない**（純粋な参考情報のため。取りこぼし自体は事前チェックで検出済み）
- **D. 仕様準拠チェック**: SKILL.mdに記載した約束事項（余白なし・次質問非食い込み・再エンコード方式・終端3段補正の適用・出力ファイル一式・命名規則・qaモードでフィラー検出なし）を機械照合する。**SKILL.mdの仕様を変更したら、この一覧（editor.pyのverify_clips内 compliance_rows）も同時に更新すること**

総合判定は「✅ 合格」または「⚠️ 要確認N件」。⚠️が0件でも、境界検査の偽陽性が疑われる場合は該当クリップを実際に視聴して確認する。

## 語尾を手動で確認するコマンド

Whisperの単語終了時刻は実際の発声より0.2〜0.5秒早く出ることがある。`refine_endings_by_silence` が自動補正するが、手動確認は文字起こしの時刻ではなく波形で行う:

```bash
ffmpeg -i <clip.mp4> -af volumedetect -f null -   # mean_volume を確認
ffmpeg -ss <末尾5秒前> -i <clip.mp4> -af silencedetect=noise=<mean-6>dB:d=0.3 -f null -
```

## 冒頭マーカー警告の切り分け方

`qa_report.md` の「冒頭に質問マーカーが見当たらない」は3パターンで発生する:

1. **tinyモデルの誤読**（例:「質問」→「スモン」）— 検査用の高速・低精度モデル特有の誤認識
2. **本当の境界ズレ** — クリップが前の回答の途中から始まっている
3. **定型句を使わない質問** — 「◯つ目の質問です」のような前振りがなく、いきなり内容から始まる

切り分け方: `transcript.json`（large-v3で生成、精度が高い）で該当クリップの冒頭付近の単語を確認する。large-v3側で正しく質問フレーズが認識されていれば1番（誤検知）と判断できる。それ以外は実際の文言を読んで2番・3番を判断する。

## 無音検出の閾値について

音源の音量が小さい（Zoom録画などは平均-40dB程度のことがある）場合、固定閾値では無音検出が反応しない。`refine_endings_by_silence` は閾値を固定値ではなく `mean_volume - 6dB`（音源ごとに自動算出）で使うため、通常は問題にならない。

## finalize.py の警告バイパス

`qa_report.md` に⚠️が残っていると `finalize.py` は最終配置を実行しない。内容を確認し、実害がないと判断できる場合のみ、警告内容をユーザーに提示して明示的な承認を得た上で `finalize.py --force` を使う（無条件バイパスにしない）。
