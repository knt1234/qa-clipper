## P0: 品質に直結する修正（最優先）

### A. クリップ切り出しの精度修正 【最重要】
- **現状の問題**: `editor.py` の `extract_qa_clips` が `-c copy`（無劣化コピー）で切り出している。コピーはキーフレーム単位でしか切れないため、**指定時刻から数秒ズレる／クリップ冒頭が乱れる（映像が止まる・真っ黒になる）** ことがある。Zoom録画はキーフレーム間隔が長く、ズレが大きくなりやすい。
- **修正**: `-c copy` をやめて再エンコードする。`remove_fillers` と同じ設定を使う:
  `-c:v libx264 -crf 18 -preset fast -c:a aac -b:a 192k`
  `-ss`/`-to` は入力前（`-i` の前）に置いたままでよい（再エンコード時は正確）。
- **影響**: 処理時間は増える（15分動画で数分程度）が、切り出し位置が正確になる。

### B. 余白（padding）が次の質問に食い込む問題
- **現状の問題**: `a_end` は「次の質問が始まる直前」なので、後ろに3秒の余白を足すと**次の質問の冒頭3秒が毎クリップの末尾に映り込む**。
- **修正**: `extract_qa_clips` で、各クリップの終了時刻を「次のペアの `q_start`」でクランプ（上限制限）する。最後のクリップのみ動画末尾まで余白可。前側の3秒余白は現状維持（ユーザーの既存運用: 短すぎると修正不可のため）。

### C. 解析結果のバリデーション追加
- **現状の問題**: Claude が返した `qa_pairs` をそのまま信じて切り出している。順序が乱れている・重複している・動画の長さを超えている場合に壊れたクリップができる。
- **修正**: `analyzer.py` に検証関数 `validate_qa_pairs(qa_pairs, duration)` を追加:
  1. `q_start` 昇順にソート
  2. `q_start >= a_end` のペアは除外して警告表示
  3. `0 <= q_start < a_end <= duration` にクランプ
  4. 前のペアと大きく重複（50%以上）するペアは除外して警告表示
  5. `title` が空なら `質問N` で補完

### D. qaモード時はフィラー検出を省略
- **現状の問題**: `--mode qa` でもプロンプトはフィラー検出まで要求している。フィラーは件数が多く、**出力トークン上限（8192）に達して JSON が途中で切れ、解析全体が失敗するリスク**がある。トークンの無駄でもある。
- **修正**: `analyze(words, model, mode)` に mode を渡し、プロンプトを2種類に分ける（qa用 / filler用 / both用）。qa用プロンプトからフィラーの節を丸ごと削除。

## P1: 使い勝手・速度の改善

### E. 切り出し前のレビュー工程 【運用ルールとの整合】
- **背景**: ユーザーは「編集完了後に確認・指摘を整理してから反映する」運用を確立している。切ってから直すより、**切る前に一覧を確認**できるほうがよい。
- **設計**: 解析後・切り出し前に `output/qa_list.md` を生成する:
  ```
  | # | タイトル | 開始 | 終了 | 長さ | 質問の冒頭 |
  |---|---------|------|------|------|-----------|
  | 1 | 集客について | 0:30 | 2:15 | 1:45 | 「集客で一番大事なのは…」 |
  ```
  - 「質問の冒頭」は transcript から q_start 以降の最初の30文字を抜き出す
  - main.py に `--review` フラグを追加: qa_list.md を出力して一時停止し、確認を促す
  - **スキル実行時（Claude Code経由）は必ず**: 解析→qa_list.mdの内容をチャットに表示→ユーザーOK→切り出し、の順で進める（SKILL.mdに明記）

### F. 文字起こしの高速化（faster-whisper 移行）
- **現状**: openai-whisper（CPU実行）。15分動画で15〜30分かかる。
- **修正**: `faster-whisper` に置き換え（`pip3 install faster-whisper`）。同じ large-v3 モデルで**3〜8倍高速・精度同等**。`transcriber.py` の `transcribe()` 内部だけの差し替えで、入出力形式（word/start/end のリスト）は変えない。
- 置き換え後も `--model` オプションはそのまま動くこと。

### G. エラー時に ffmpeg のエラー内容を表示
- **現状**: `capture_output=True` + `check=True` のため、失敗すると「エラーになった」ことしか分からない。
- **修正**: subprocess 呼び出しを共通ヘルパー `_run_ffmpeg(cmd)` にまとめ、失敗時に stderr の末尾20行を表示して終了する。

### H. ffmpeg / ffprobe のパス解決
- **現状**: `editor.py` と `downloader.py` に `/opt/homebrew/bin/ffmpeg` がハードコード。環境が変わると壊れる。
- **修正**: モジュール先頭で `shutil.which("ffmpeg")` / `shutil.which("ffprobe")` で解決。見つからなければ「brew install ffmpeg を実行してください」と案内して終了。

### I. 出力フォルダの自動命名
- **現状**: `./output` 固定 → output, output2, output3… と手動で増えて散らかっている（実際に6フォルダ存在）。
- **修正**: `--output` 未指定時のデフォルトを `./output_{動画ファイル名}_{YYYYMMDD}` にする。同名フォルダが既にある場合は上書きせず `_2`, `_3` を付ける。


### J. JSONパース失敗時のリトライ
- **現状**: Claude の応答が JSON として読めないと即クラッシュ。
- **修正**: パース失敗時に1回だけ再実行（`temperature` はデフォルトのまま）。2回失敗したら生の応答を `analysis_raw.txt` に保存してエラー終了（原因調査できるように）。

## P2: 余裕があれば

- **K. 長尺対応**: 45分超の動画は transcript をコンテキストに収めきれない可能性。10分単位（前後1分オーバーラップ）で分割解析し、境界のペアをマージする。今の用途（15分前後）では不要なので、実装は後回しでよい。
- **L. transcript の圧縮**: 現在は word 単位の JSON をそのまま送っており冗長。`"開始秒 テキスト"` の行形式に変換して送ればトークンを約1/3に削減できる（プロンプトも合わせて修正）。
- **M. cache_control の削除**: 1回きりの呼び出しでは prompt cache は無意味で、書き込み料金の分だけ割高。`analyzer.py` から削除。
