## 背景・目的

もう一つの動画編集プロジェクト（/video-pipeline）と同じ運用を qa-clipper にも適用する:
- **完成物だけローカルに残す**（クリップMP4のみ）
- **完成物＋それ以外すべてを Google Drive にバックアップ**（クリップ + audio.wav + 各JSON + レポート）
- ユーザーが完成物を承認した後に自動実行する

既存メモリ（feedback-video-pipeline-review）のファイル配置ルールに準拠する。

## ユーザー確定事項（2026-07-08）

1. ローカル格納は **動画ごとのサブフォルダ**（既存の `_完成版.mp4` と混ぜない）
2. ローカルに残すのは **クリップのみ**（qa_list.md / qa_report.md 等のレポート類は Google Drive バックアップにのみ保存）

## 実装: 新規スクリプト `finalize.py`

Claude Code経由の運用では、クリップのレビュー承認は**チャット上で対話的に行われる**ため、バッチ実行の main.py 内では承認を待てない。したがって承認後に別途呼び出す独立スクリプトとして実装する。

### CLI

```bash
python3 finalize.py --output "output_{動画名}_{日付}" [--keep-local] [--yes]
```

| オプション | 説明 |
|---|---|
| `--output` | 対象の出力フォルダ（必須） |
| `--keep-local` | ローカル作業フォルダを削除しない（バックアップと完成品配置のみ行う安全モード） |
| `--yes` | 確認プロンプトをスキップして実行（Claude Codeがチャットで承認を得た後に付与） |

`--yes` なしで実行した場合は、**これから行う操作（コピー先・削除対象・削除サイズ）を一覧表示して y/N を待つ**。

### 処理順序（安全順序を厳守）

コピーは可逆、削除は不可逆。**検証を通過するまで一切削除しない。**

```
1. 事前チェック
   - output フォルダ存在・qa/ に .mp4 が1本以上あること
   - qa_report.md が存在し、総合判定が「✅ 合格」であること
     → ⚠️要確認 が残っている場合は中止（「未承認の警告があります」と表示）
   - 配置先の親フォルダ（Documents完成品 / GDrive中間ファイル）が存在すること
     → GDriveがマウントされていなければ中止（未マウントで空フォルダに書くと事故る）

2. ローカル完成品へコピー（local→local, 可逆）
   - Documents/動画編集_完成品/QA_{動画名}/ を作成（既存なら中身を確認し、上書き前に警告）
   - qa/*.mp4 を cp でコピー

3. GDriveバックアップへコピー（local→GDriveマウント, 可逆）
   - 動画編集_中間ファイル/qa_{動画名}/ を作成
   - output_xxx/ の中身一式（qa/ 含む）を cp -R でコピー

4. 検証（削除の前提条件）
   - ローカル完成品: qa/内の .mp4 本数とコピー先の本数が一致、各ファイルのバイトサイズ一致
   - GDriveバックアップ: output_xxx/ 内の全ファイル本数とコピー先の本数が一致、各ファイルのバイトサイズ一致
   - 1つでも不一致なら削除せず中止し、不一致リストを表示

5. ローカル作業フォルダ削除（不可逆, --keep-local 時はスキップ）
   - 検証を全通過した場合のみ output_{動画名}_{日付}/ を削除
   - 関連ログ（output_..._run.log 等）も併せて削除するか確認（削除対象に含める）

6. 完了サマリ表示
   - ローカル完成品パス（クリップN本）
   - GDriveバックアップパス（合計サイズ）
   - 削除したローカル容量
```

### 実装上の注意（既存の教訓を反映）

- **GDriveへの直接レンダリングは避ける**（lessons: FUSE破損）。本スクリプトは単純な `cp` のみで、重いffmpeg処理はしない。それでもコピー後にバイトサイズ照合を必ず行い、不一致なら削除しない
- GDriveはマウント確認を必須にする。`/Users/Kenta/Library/CloudStorage/GoogleDrive-kenta0720fila@gmail.com/マイドライブ/` が存在しない状態でパスを掘ると、同期されないローカルの偽フォルダを作ってしまうため、親フォルダの存在チェックを事前チェックに入れる
- 既存の同名フォルダがある場合（再実行時など）は無断上書きせず、内容を表示して確認を求める
- パスはすべて絶対パスで扱い、`shutil` を使う（シェルのグロブ展開に頼らない。日本語・`&` 混じりのパスで事故らないため）

## テスト（実データ使用）

現存する2つの出力フォルダのうち片方をテストに使う。**破壊テストになるため、まず `--keep-local --yes` でコピーと検証だけ通し、削除は別途確認する。**

1. `finalize.py --output "output_20260302..." --keep-local --yes` を実行
   - Documents/動画編集_完成品/QA_20260302.../ にクリップ4本がコピーされる
   - GDrive/.../qa_20260302.../ に output一式がコピーされる
   - 検証で全ファイルのサイズ一致が確認され「削除はスキップ（--keep-local）」と表示される
2. サイズ照合ロジックの単体確認: わざと1ファイル欠けさせた状態で検証が「不一致」を返し削除に進まないこと
3. 事前チェック: qa_report.md に⚠️が残る状態（20260706フォルダはレポート未生成）では「合格レポートがない」で中止すること
4. 構文確認: `python3 -c "import finalize"`

削除まで含む本番実行は、テスト通過をユーザーに提示し承認を得てから行う。
