## 背景（2026-03-02動画のテストで発覚した問題）

- Claude Haiku が「今日最後の質問ですね」(483.8秒) という明確な区切りを見逃し、3問目と4問目が1本に結合された
- 発見できたのはユーザーがプレビューで気付いたから。**検出漏れの機械チェックも、完成後の自動レビューも無かった**
- さらに、SKILL.md に約束として書いてあること（余白なし・次質問非食い込み・再エンコード等）が**実際の出力で守られているかを照合する仕組みが無い**。ドキュメントと実態がズレても気付けない

## 設計の柱（3つ）

1. **事前チェック**: Claude解析をルールベースの質問マーカー検出と突き合わせ、検出漏れ・結合を切り出し前に発見する
2. **事後検証（クリップ全体）**: 生成物そのものを多面的に検査し `qa_report.md` を出力する
3. **仕様準拠チェック**: SKILL.md に記載した約束事項を1項目ずつ機械照合し、同レポートに含める

## 実装1: 質問マーカー検出とクロスチェック（analyzer.py に追加）

### `detect_question_markers(words) -> List[dict]`

transcript 全文を結合し正規表現でマーカーを検出、`[{"time": 483.8, "phrase": "最後の質問", "strength": "strong"}]` を返す。
文字位置→タイムスタンプは単語ごとの文字数累積で逆引き（今回のデバッグ手法と同じ）。

- **strong**: `続いての質問` / `次の質問` / `最後の質問` / `最初の質問` / `[0-9一二三四五六七八九十１-９]+つ目の質問` / `一つ目の質問`
- **weak**（補助情報、単独では警告にしない）: `質問です` / `質問ですが` / `ご質問`

### `cross_check_qa_pairs(qa_pairs, markers) -> List[str]`

許容差 ±5秒。警告を返す（空なら合格）:
1. strongマーカーがどのペアの q_start とも一致しない → `[検出漏れの疑い] 8:03「最後の質問」に対応するペアがない。q_start=483.8 での分割を検討`
2. ペア長が全ペア中央値の1.8倍超 → `[結合の疑い] #3 は 5:25 で突出して長い`

### main.py への組み込み

- Claude解析直後に実行。警告は qa_list.md 末尾の「⚠️ 要確認」セクション＋コンソールに出力
- **警告がある状態では切り出しに進まない**。CLI単体実行用に `--force` オプションを新設
- Claude Code運用: 警告提示 → analysis.json 修正 → 警告ゼロ確認 → 切り出し

### プロンプト改善（QA_SECTION に1項目追加）

```
- 「続いての質問」「◯つ目の質問」「最後の質問」などの前振りフレーズが出たら、必ずそこで新しいペアを開始すること。1つのペアに複数の質問を含めてはならない
```

## 実装2: 事後検証 — クリップ全体の検査（editor.py に `verify_clips` を追加）

`verify_clips(video_path, clip_paths, qa_pairs, words, output_dir) -> Path`
クリップ生成後に必ず実行し `qa_report.md` を生成。検査は4系統:

### A. ファイル健全性（クリップごと）
1. ファイルが存在しサイズ > 0
2. ffprobe で映像ストリーム・音声ストリームが両方あること
3. 実測長と (a_end - q_start) の差が ±1.5秒以内
4. 末尾1秒のフレームがデコードできること（`ffmpeg -sseof -1 -i clip -frames:v 1 -f null -` がエラーなく通る = 尻切れ破損なし）

### B. 境界検査（クリップごと）
1. 冒頭6秒を faster-whisper `tiny` で文字起こし → 質問マーカー（strong/weak）を含むかを記載。含まない場合は⚠️（前の回答の続きが混入している可能性）
2. 末尾6秒を同様に文字起こし → **strongマーカーを含んだら⚠️（次の質問が混入）**。末尾全文はレポートに記載し、文として完結しているかは人間が最終判断

### C. カバレッジ検査（全体）
1. クリップ群の合計時間と、隣接クリップ間の「使われていない区間」を算出
2. 10秒を超える未使用区間があれば、その区間の transcript 冒頭30文字を添えて⚠️
   （挨拶・雑談なら問題なし、質問の取りこぼしなら気付ける）
3. 件数一致: クリップ数 = qa_list.md のペア数

### D. 仕様準拠チェック（SKILL.md の約束事項の機械照合）

SKILL.md に書いた仕様を1項目ずつ照合する。**この表が「skillsにまとめたことが実装できているか」の担保**:

| 準拠項目 | SKILL.md の記載 | 照合方法 |
|---|---|---|
| 余白なし | 話始め〜話終わりぴったり | 実測長 ≒ a_end − q_start（±1.5秒、Aの3と共用） |
| 次質問非食い込み | 次の質問の冒頭が混入しない | Bの2（末尾にstrongマーカーなし） |
| 再エンコード方式 | -c copy は使わない | ffprobe でコーデックが h264/aac、かつ開始タイムスタンプが 0 付近（copy 特有のズレがない） |
| 終端3段補正 | 波形補正まで通す | qa_pairs の a_end が analysis.json の生値と異なる（補正が適用された痕跡）こと。全ペア一致なら⚠️ |
| 出力一式 | transcript/analysis/qa_list/qa/ | 4点の存在確認（qa_report.md 自身も追加） |
| 命名規則 | NNN_タイトル.mp4 | ファイル名が `^\d{3}_.+\.mp4$` に一致し連番であること |
| モード仕様 | qa モードではフィラー検出しない | analysis.json の fillers が空であること（qaモード時） |

### qa_report.md の形式

```markdown
# クリップ検証レポート（YYYY-MM-DD HH:MM）
総合判定: ✅ 合格 / ⚠️ 要確認 N件

## クリップ検査
| # | ファイル | 長さ | 健全性 | 冒頭 | 末尾 | 判定 |
|---|---------|------|--------|------|------|------|
| 1 | 001_xxx.mp4 | 2:10 | ✅ | 「1つ目の質問ですが…」 | 「…と思います」 | ✅ |

## 仕様準拠チェック
| 項目 | 結果 |
|---|---|
| 余白なし | ✅ |
| 次質問非食い込み | ✅ |
| （…全7項目…） | |
```

### main.py への組み込み

- `extract_qa_clips` 直後に `verify_clips` を必ず実行
- ⚠️が1件でもあれば総合判定を「要確認」としてコンソールに目立たせる
- Claude Code運用: **レポートの表をチャットに提示し、ユーザーの最終OKで完成**。⚠️があれば先に修正して再切り出し→再検証

## 実装3: ノウハウ蓄積の運用（⑦ ふりかえり記録）

**目的: ユーザーの指摘・確認・修正指示を毎回記録し、次回以降の同種ミスを仕組みで防ぐ。**
コード実装は不要（運用ルール）。SKILL.md と lessons.md への記載で担保する。

### 運用ルール（SKILL.md に明記する内容）

⑥の最終OKが出たら、完了報告の前に必ず以下を行う:

1. **整理**: セッション中にユーザーが行った指摘・修正指示・質問・確認を時系列で洗い出す
2. **分類の提案**: 各項目を次の3種に分類してユーザーに提示:
   - **ルール化**（SKILL.md の仕様・チェックリスト・トラブルシューティングに反映すべきもの）
   - **記録のみ**（lessons.md に経緯として残すもの）
   - **今回限り**（この動画固有の事情で、記録不要のもの）
3. **確認**: 「この分類でルール化・記録してよいか」をユーザーに確認する（無断で SKILL.md を書き換えない）
4. **反映**: 承諾を得たものを反映する。**SKILL.md に仕様を足した場合は、qa_report.md の仕様準拠チェック項目も同時に追加する**（ドキュメントとチェックのセット更新。教訓⑥と同じ原則）

### lessons.md の記録テンプレート（追記フォーマットを統一）

```markdown
## YYYY-MM-DD 対象動画名（または作業内容）

### 指摘・確認事項
| # | ユーザーの指摘・確認 | 原因 | 対応 | 扱い |
|---|---|---|---|---|
| 1 | 終わりに次のQAが含まれる | AIが「最後の質問」を見逃し | analysis.json手修正+クロスチェック実装 | ルール化済み |

### 一般化した教訓
- （あれば。1〜3行で）
```

- 記録は**セッション単位で1ブロック**。細かすぎる粒度（コマンド単位）では書かない
- 教訓が既存の教訓と重複する場合は新規追加せず、既存項目に「再発 YYYY-MM-DD」と添える（同じ教訓が増殖しないように）

## 実装の進め方（Sonnet向け）

1. analyzer.py: `detect_question_markers` / `cross_check_qa_pairs` + QA_SECTION追記
2. editor.py: `verify_clips`（A〜D全系統。tiny モデル利用、一時wavは tempfile で後始末）
3. main.py: ②⑤組み込み、`--force` 新設
4. SKILL.md / lessons.md 更新
5. テスト（20260302動画の実データを使用）:
   - マーカー検出が 18.8 / 150.8 / 300.2 / 483.8 の4件（strong）を返す
   - 3ペア版 analysis.json（結合状態を一時的に復元）で「検出漏れの疑い 483.8」「結合の疑い #3」の両警告が出る
   - 修正済み4ペア版で警告ゼロ
   - 生成済み4クリップへの verify_clips で、A〜D全系統が✅（仕様準拠7項目含む）になり qa_report.md が生成される
   - 故意の破壊テスト1件: qa_pairs の a_end を analysis.json の生値のままにして「終端3段補正」チェックが⚠️になること
6. 構文確認: `python3 -c "import editor, analyzer, transcriber, main"`
